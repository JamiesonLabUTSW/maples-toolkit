# MAPLES Rubric Specification

**Rubric Maker YAML Format** Version 1.0 - June 2026

## Overview

The MCP `upload_rubric` tool accepts rubric YAML text through its `content` argument
when `filename` ends in `.yaml` or `.yml`. MAPLES converts this row-oriented YAML into
its internal workbook format before validation and storage.

Use this format when generating a rubric for direct upload:

```yaml
name: example-rubric
description: Example multimodal rubric
station: Default
version: "1"
context: ""
rubric:
  - ItemKey: NOTE-001
    Category: History
    QuestionName: Documents the chief concern and relevant history.
    ScoringLogic:
      Score1: Missing or unsupported.
      Score2: Partially documented.
      Score3: Clearly and accurately documented.
    Mode: note
    Technique: Look for explicit written-note evidence.
    Purpose: Assess completeness and accuracy.
    AdditionalContext: Accept equivalent clinical wording.
```

## Top-Level Fields

| Field | Required | Description |
| --- | --- | --- |
| `rubric` | Yes | Non-empty list of rubric item mappings. |
| `name` | No | Rubric name. Defaults to the uploaded filename without its extension. |
| `description` | No | Rubric description. Defaults to `name`. |
| `station` | No | Station sheet name. Defaults to `Default`; if provided, it must not be blank. |
| `version` | No | Rubric version metadata. Defaults to `"1"`. |
| `context` | No | Optional rubric-wide context. Defaults to an empty string. |

## Rubric Item Fields

| Field | Required | Description |
| --- | --- | --- |
| `ScoringLogic` | Yes | Non-empty mapping of sequential scoring levels named `Score1`, `Score2`, and so on. |
| `ItemKey` | No | Unique item identifier. Defaults to `ITEM-001`, `ITEM-002`, and so on. |
| `Mode` | No | Modality: `audio`, `video`, or `note`. Defaults to `note`. Input is normalized to title case. |
| `Category` | Recommended | Logical grouping for the item. Converted to the internal `Section` field. |
| `QuestionName` | Recommended | Assessment question or skill description. Converted to `QuestionText`. |
| `Technique` | No | Exact evidence or technique the grader should look for. |
| `Purpose` | No | Educational or technical rationale for the item. |
| `AdditionalContext` | No | Clarifications, acceptable alternatives, constraints, or grading cautions. |

For rubrics generated by this skill, use `Mode: note`, `Mode: audio`, or `Mode: video`
for each item according to the evidence source being graded, and include `Category`,
`QuestionName`, `Technique`, `Purpose`, and `AdditionalContext`.

## Scoring Logic

`ScoringLogic` must contain one or more levels ordered from lowest to highest.
Keys must be sequential and must start at `Score1`.

Valid:

```yaml
ScoringLogic:
  Score1: Missing.
  Score2: Partially documented.
  Score3: Clearly documented.
```

Invalid:

```yaml
ScoringLogic:
  Score1: Missing.
  Score3: Clearly documented.
```

The invalid example fails because `Score2` is missing.
The key order also matters: `Score1`, `Score2`, and `Score3` must appear in that order.

## Validation Rules

Uploads fail when:

- the YAML root is not a mapping;
- `rubric` is missing, is not a list, or is empty;
- a rubric item is not a mapping;
- `ScoringLogic` is missing, is not a mapping, or is empty;
- `ScoringLogic` keys are not sequential `Score1` through `ScoreN`;
- `station` is present but blank;
- the rubric name cannot be derived from `name` or the filename.

Use unique `ItemKey` values.
Duplicate keys fail downstream workbook validation.

## Quality Rules

- Grade only what can be found in the selected modality.
- Keep each item single-purpose and evidence-based.
- Prefer concrete evidence over vague judgments.
- Do not invent case facts.
  Put uncertainty or acceptable alternatives in `AdditionalContext`.
- Make each scoring level independently scorable from the item's declared modality.
- For `Mode: note`, grade only written-note evidence.
- For `Mode: audio`, grade only what can be heard or reliably transcribed.
- For `Mode: video`, grade only what can be visually observed.
- Do not mix evidence channels inside a single item.
  Split multimodal criteria into separate rows with separate `Mode` values.
